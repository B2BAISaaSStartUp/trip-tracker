# Трекер подорожей (Trip Tracker)

> Статус: у розробці (ЛР4 — базова структура коду). Фінальний README збирає Дикий Д. М. (робота 20).

Сервіс для запису маршрутів подорожей, позначок і фото на карті. Модульний моноліт на ASP.NET Core 8, мобільний клієнт на Flutter (Android), веб-клієнт на Blazor WebAssembly.

## Структура репозиторію

| Каталог | Вміст |
|---|---|
| `src/server/TripTracker.Api` | REST Endpoints: конвеєр запитів, контролери, конфігурація |
| `src/server/TripTracker.SharedKernel` | Спільні DTO та тип результату операції |
| `src/server/TripTracker.DataAccess` | Абстракція доступу до даних, базовий контекст EF Core |
| `src/server/Modules/<Модуль>` | Бізнес-модулі: Identity, Trips, Tracking, Markers, Photos, Profile, Administration |
| `src/mobile/trip_tracker_app` | Flutter-застосунок для Android |
| `src/web/TripTracker.Web` | Веб-клієнт Blazor WebAssembly |
| `tests/` | Модульні та архітектурні тести |
| `docs/` | Архітектура, вимоги, тест-план, правила роботи з Git |
| `deploy/local/` | Docker Compose для локальної розробки |
| `.github/` | Шаблон PR, налаштування GitHub (CI — за потреби) |

## Робота з репозиторієм (коротко)

- Гілка на кожну роботу: `<тип>/TT-<номер>-<опис>`, типи: `feature`, `fix`, `test`, `docs`, `ci`, `chore`.
- Коміти: `TT-<номер> <що зроблено>` — англійською, до 72 символів.
- Прямі коміти в `main` заборонені: зміни потрапляють туди лише через Pull Request з код-рев'ю і ≥ 1 схваленням.
- Злиті гілки не видаляємо до оцінювання ЛР4.
